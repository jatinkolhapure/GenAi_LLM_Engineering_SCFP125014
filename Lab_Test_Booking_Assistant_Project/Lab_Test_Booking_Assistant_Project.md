# Lab Test Booking Assistant

**An AI-powered diagnostic laboratory appointment booking system built with Python, SQLite, Groq, and LangChain.**

## 1. Project Overview

The Lab Test Booking Assistant is an AI-powered application that allows users to explore diagnostic laboratory tests, check appointment availability, book test slots, and cancel existing bookings through a conversational interface.

The project demonstrates how AI agents can interact with databases and external information sources while maintaining privacy, security, reliability, and human control over sensitive operations.

The complete implementation is provided in a single Jupyter Notebook designed to run on Kaggle.

## 2. Project Objectives

- Build an AI agent capable of interacting with structured database tools.
- Automate diagnostic test discovery and appointment booking.
- Implement human approval before database-changing operations.
- Maintain separate booking records for multiple users.
- Preserve conversation context across multiple interactions.
- Integrate external web search for general health information.
- Implement privacy protection and reliable error handling.

## 3. Key Features

### Diagnostic Test Management
- Browse available laboratory tests.
- Explore tests by category.
- Check appointment slot availability.
- Identify tests with no available slots.

### Appointment Management
- Book available appointment slots.
- Cancel existing confirmed bookings.
- Prevent duplicate bookings.
- Validate test and slot information before booking.
- Generate booking receipts using database records.

### Human-in-the-Loop Approval
The system requires explicit approval before executing:
- `book_test`
- `cancel_booking`

Users can approve or reject sensitive operations. Rejected operations must not modify the database.

### Multi-User Support
- Supports two demonstration users: `user1` and `user2`.
- Maintains separate booking records.
- Prevents users from viewing another user's bookings.
- Prevents unauthorized cancellation of another user's booking.

### Conversation Memory
Uses an in-memory checkpointer to retain conversation context across turns within the same conversation thread.

### General Health Information
Uses an external web-search integration to retrieve general health information.

**Important:** Test prices and appointment availability are obtained from the SQLite database, not generated by the language model.

## 5. System Architecture

The application follows a tool-based AI agent architecture.

```text
                  User
                   |
                   v
          Interactive Chat Loop
                   |
                   v
              AI Agent
                   |
          +--------+--------+
          |                 |
          v                 v
     Read Tools         Write Tools
          |                 |
          v                 v
       SQLite          Human Approval
          |                 |
          |                 v
          |            SQLite Updates
          |
          v
     Booking Results

          AI Agent
              |
              v
       General Web Search
```

## 6. Database Design

The application uses SQLite with three primary tables.

| Table | Description |
|---|---|
| `tests` | Stores diagnostic test details and categories |
| `slots` | Stores appointment slots and booking capacity |
| `bookings` | Stores user bookings and their statuses |

The notebook creates and seeds the database automatically, making setup straightforward.

The sample database includes:
- 8 diagnostic tests across different categories.
- 24 appointment slots.
- At least one test with no available slots.

## 7. Agent Tools

### Read Tools

| Tool | Function |
|---|---|
| `list_tests` | Lists diagnostic tests |
| `check_slots` | Checks appointment availability |
| `my_bookings` | Retrieves the current user's bookings |

### Write Tools

| Tool | Function |
|---|---|
| `book_test` | Creates a booking after approval |
| `cancel_booking` | Cancels a booking after approval |

### External Information Tool

| Tool | Function |
|---|---|
| `general_health_search` | Retrieves general health information from the web |

The language model does not generate or execute SQL queries. Database operations are implemented in controlled Python tools using parameterized SQL statements.

## 8. Security and Reliability

The application incorporates the following safeguards:

- **Runtime user context:** User identity is supplied through runtime context, not model-generated tool arguments.
- **Parameterized SQL:** Uses SQL placeholders to reduce SQL injection risks.
- **Booking ownership validation:** Prevents unauthorized access and cancellation.
- **Duplicate booking prevention:** Validates existing confirmed bookings.
- **Human approval:** Requires approval for booking and cancellation operations.
- **Email redaction:** Removes email addresses before user messages reach the agent.
- **Retry mechanism:** Retries temporary failures in the slot-checking tool.
- **Safe reruns:** Initializes and seeds the database without creating duplicate seed records.
- **Symptom safety:** Avoids diagnosing users or recommending laboratory tests based on symptoms.

## 10. Setup and Execution

### Prerequisites

- Kaggle account
- Groq API key
- Internet access enabled in Kaggle Notebook settings

### Configuration

1. Open the notebook in Kaggle.
2. Enable Internet access in notebook settings.
3. Open Kaggle Secrets.
4. Add a secret named `GROQ_API_KEY`.
5. Store your Groq API key as the secret value.
6. Enable notebook access to this secret.

### Run the Application

1. Execute the notebook cells in order.
2. Allow the database to initialize.
3. Initialize the AI agent.
4. Run the interactive assistant:

```python
interactive_loop()
```

5. Sign in using `user1` or `user2`.
6. Interact with the assistant to list tests, check slots, book appointments, and cancel bookings.

Type `exit` to end the interactive session.
